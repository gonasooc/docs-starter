# UI 디자인 기준

> 선택 문서 템플릿입니다. UI 디자인 기준이 필요한 프로젝트에서만 사용합니다. 실제 코드와 가능하면 렌더링된 화면을 확인해 작성하고, 확인하지 못한 내용은 `미확인`, 결정하지 않은 내용은 `미정`으로 남기세요.

UI의 시각적 기준과 상호작용·반응형·접근성 기준을 다룹니다. 시스템 구조는 [docs/architecture.md](architecture.md), 기술 스택·구현 도구 설정·검증 명령은 [docs/specs.md](specs.md)에서 관리합니다.

## 참고할 코드와 화면

[스타일·디자인 토큰·공통 컴포넌트의 원본 파일과 대표 화면을 연결합니다. 코드와 화면을 확인한 날짜·환경·범위를 적고, 화면을 직접 확인하지 못했다면 그 한계를 밝힙니다.]

토큰 값이나 컴포넌트 목록 전체를 복제하지 않고, 필요한 사용 원칙과 원본 경로를 남깁니다.

## 관찰된 구현

[현재 코드와 화면에서 확인한 색상·타이포그래피·간격·레이아웃·컴포넌트 패턴을 근거와 함께 짧게 적습니다. 일부 화면에서만 확인한 패턴을 프로젝트 전체의 규칙으로 일반화하지 않습니다.]

## 합의된 디자인 기준

[앞으로 따라야 한다고 합의한 기준만 이유와 함께 적고, 근거 작업을 연결합니다. 기존 코드에 있다는 이유만으로 디자인 규칙으로 확정하지 않습니다.]

- 시각적 방향과 레이아웃: [의도한 인상, 정보 위계, 색상·타이포그래피·간격의 사용 기준]
- 공통 컴포넌트와 상태: [재사용 기준, 기본·포커스·비활성·로딩·오류 등 필요한 상태 표현]
- 반응형과 접근성: [화면 크기별 변화, 키보드 사용, 대비·동작 효과 등 합의된 기준]

## 불일치와 미정 사항

- [화면 간 스타일 차이, 코드와 합의된 기준의 불일치, 확인 또는 결정이 필요한 내용. 없으면 ‘없음’.]

## 디자인 확인 방법

[변경 후 확인할 대표 화면, 화면 크기, 컴포넌트 상태와 사용자 조작을 적습니다. 실제 확인 결과와 미확인 범위는 개별 작업 문서에 남깁니다.]
